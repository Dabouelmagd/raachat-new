# رع شات (Starter Codebase)

هيكل بداية لواجهة الويب الخاصة بتطبيق «رع شات»، مبني مباشرة على وثيقة متطلبات
المنتج (PRD) المرفقة.

> بيانات هذا المشروع محلية بالكامل (in-memory) — **تتصفر عند تحديث
> الصفحة**. مفيش مصادقة أو اتصال حقيقي بخادم. الهدف تسريع التطوير
> الفعلي، مش نسخة إنتاج جاهزة.

## التقنيات

يطابق طبقة العميل الموصى بها في القسم 6 من الـ PRD لتطبيق الويب/سطح المكتب:

- **React 18 + TypeScript** عبر **Vite**
- **Tailwind CSS** مع ألوان العلامة كامتداد جاهز (`tailwind.config.js`)
- **react-router-dom** للتنقل بين الشاشات
- **lucide-react** لمكتبة الأيقونات الخطية الموحّدة

للموبايل (iOS/Android)، الوثيقة توصي بـ **Flutter** — هذا الهيكل الحالي
يغطي الويب فقط.

## التشغيل

```bash
npm install
npm run dev       # خادم التطوير على http://localhost:5173
npm run build     # نسخة إنتاج في dist/
```

## هيكل المشروع

```
src/
  types.ts                 # أنواع البيانات المشتركة (Thread, Message, VoiceRoom, Story...)
  theme/colors.ts           # لوحة الألوان — المصدر الوحيد للحقيقة (راجع القسم 2)
  store/
    seed.ts                   # بيانات أولية وهمية (جهات اتصال، محادثات، غرف، قصص)
    AppContext.tsx              # "الباك إند" الوهمي بالكامل: Context + reducer
  data/mock.ts               # بيانات تجريبية لقسم الخدمات فقط
  components/
    Header.tsx                 # الرأس المشترك + علامة عين حورس (HorusMark)
    BottomNav.tsx                # التنقل السفلي: الدردشات / الغرف / الخدمات / الحساب
    MessageBubble.tsx              # فقاعة رسالة: رد مقتبس، تفاعلات، تعديل، حذف
    StoriesBar.tsx                   # شريط القصص أعلى شاشة الدردشات
    StoryViewer.tsx                    # عارض القصص كامل الشاشة (progress bar تلقائي)
    AddStorySheet.tsx                    # نشر قصة جديدة
    NewChatSheet.tsx                       # اختيار: دردشة فردية جديدة أو إنشاء جروب
  screens/
    ChatsScreen.tsx             # ① قائمة المحادثات (فردية + جروبات) + شريط القصص
    ChatScreen.tsx                # ② الدردشة: إرسال حقيقي، رد، تفاعل، تعديل، حذف
    NewGroupScreen.tsx              # اختيار أعضاء الجروب ثم تسميته
    RoomsScreen.tsx                   # ③ الغرف الصوتية: إنشاء، اختيار هوية، دخول فعلي
    ServicesScreen.tsx                  # ④ الخدمات والمحفظة (لسه mock ثابت)
    AccountScreen.tsx                     # ⑥ الحساب والخصوصية
  App.tsx                      # AppProvider + التوجيه الرئيسي (react-router-dom)
```

الترقيم ①②③④⑥ يطابق ترقيم الشاشات في القسم 4 من الـ PRD.

## الحالة الحالية (بعد هذه المرحلة)

اتنفّذت **الشات + الجروبات + الروومز + قسم "نشر المحتوى" (Stories)**
بشكل حقيقي على مستوى الواجهة، بحالة محلية عبر `src/store/AppContext.tsx`
بدل بيانات ثابتة زي المرحلة اللي فاتت — يعني فعليًا تقدر:

- ترسل رسالة وتظهر فورًا في القائمة، ترد على رسالة معيّنة (quote reply)،
  تتفاعل بإيموجي، تعدّل أو تحذف رسائلك.
- تعمل جروب جديد باختيار أعضاء واسم من `NewGroupScreen`، ويظهر فورًا في
  قائمة الدردشات، وتقدر "تغادر" الجروب من شاشة معلوماته.
- تعمل دردشة فردية جديدة من "+" ← "دردشة فردية" باختيار جهة اتصال.
- تعمل غرفة صوتية جديدة، تختار هوية حقيقية أو مؤقتة (زي رحلة المستخدم أ
  بالقسم 5)، وتدخلها — وتشوف أعضاء "ينضمون" تلقائيًا كل بضع ثوانٍ
  (محاكاة فقط، مفيش صوت حقيقي بعد).
- تنشر قصة (Story) بنص ولون من لوحة العلامة، تظهر في الشريط العلوي،
  وتُشاهد بعارض كامل الشاشة بشريط تقدّم تلقائي شبيه بالستوريز المعروفة.

كل الحالة دي في الذاكرة فقط وتتصفر عند تحديث الصفحة — قسم "أهم الخطوات
التالية" تحت موضّح فيه إزاي تربطها بباك إند حقيقي دائم.

شاشة الملصقات والأفاتار الفرعوني (⑤) غير منفّذة بعد — مقترحة كجزء من
`ChatScreen` (لوحة ملصقات منبثقة) بدلًا من تبويب رئيسي مستقل.

## طبقة الحالة (`src/store/AppContext.tsx`) — أهم جزء تقرأه قبل التعديل

كل شاشات الشات/الجروبات/الروومز/القصص بتتعامل مع تطبيق بيانات وهمي عبر
`useAppState()` (قراءة) و`useAppActions()` (كتابة) بس — مفيش أي شاشة
بتلمس الحالة مباشرة. ده يعني إن ربط باك إند حقيقي **بيتم في ملف واحد**:

```ts
// دلوقتي:
sendMessage: (threadId, text, replyToId) =>
  dispatch({ type: "SEND_MESSAGE", threadId, text, replyToId }),

// بعد الربط بـ API حقيقي (مثال):
sendMessage: async (threadId, text, replyToId) => {
  const saved = await api.post(`/threads/${threadId}/messages`, { text, replyToId });
  dispatch({ type: "SEND_MESSAGE_CONFIRMED", message: saved }); // تحديث متفائل
},
```

لأي مراسلة لحظية حقيقية (بدل الإرسال المحلي)، الأنسب دمج WebSocket/Realtime
subscription جوه `AppProvider` بحيث الرسايل الواردة من السيرفر تعمل
`dispatch` بنفس الـ actions الموجودة — الشاشات مش هتحتاج تتغيّر خالص.

## أهم الخطوات التالية (غير منفّذة عمدًا)

هذه الفجوات معروفة ومتروكة عمدًا لفريق التطوير، مرتّبة تقريبًا بحسب
خارطة الطريق في القسم 8 من الـ PRD:

1. **طبقة API/باك إند حقيقية** — استبدال جسم الدوال في
   `src/store/AppContext.tsx` بنداءات فعلية (REST/GraphQL)، مع تخزين
   دائم بدل الذاكرة (راجع القسم 6: بوابة NestJS أو Go).
2. **تسجيل الدخول والحساب** — تدفق OTP بالإيميل أو الموبايل (القسم 3-د)؛
   لسه مفيش شاشة تسجيل/دخول في هذا الهيكل، وكل الشاشات تفترض "أنت" مسجّل
   دخول بالفعل.
3. **مراسلة لحظية حقيقية بين أجهزة مختلفة** — اتصال WebSocket/Realtime
   حقيقي بدل الحالة المحلية في `AppContext.tsx` (راجع القسم القبل ده).
4. **صوت حقيقي في الغرف** — الانضمام/المغادرة/الصمت في `RoomsScreen.tsx`
   حالة واجهة فقط؛ الصوت الفعلي محتاج WebRTC (LiveKit/Jitsi كما في
   القسم 6) بدل محاكاة `simulateParticipantJoin`.
5. **مكالمات صوتية وفيديو فردية** — أيقونتا الهاتف والفيديو في
   `ChatScreen.tsx` حاليًا للعرض فقط بدون منطق اتصال.
6. **تدفق دفع الفواتير الكامل** — مراجعة → مصادقة ثنائية (بصمة/PIN) →
   إيصال رقمي، كما في رحلة المستخدم (ب) بالقسم 5. الشاشة الحالية في
   `ServicesScreen.tsx` معلّمة بـ `TODO` ولسه مرحلة قادمة.
7. **تشفير من طرف إلى طرف** ومنع لقطة الشاشة على مستوى نظام التشغيل —
   قرارات تنفَّذ على مستوى تطبيقات الموبايل الأصلية بالأساس (القسم 7).

للنموذج التفاعلي الكامل لشاشة الغرفة الصوتية بتصميم أدق (قبل هذا الهيكل
البرمجي)، راجع ملف `RaChatPrototype.jsx` المُرسل في المرحلة السابقة.

## ربط الواجهة بالباك إند

- بدون `VITE_API_URL` → وضع الديمو (بيانات وهمية).
- مع `VITE_API_URL=http://localhost:4000` (انسخي `.env.example` إلى `.env`) → تسجيل دخول OTP حقيقي، محادثات/جروبات/ستوريز/مكالمات من PostgreSQL، رسائل لحظية عبر Socket.IO، رفع الصور والملفات.
- شغّلي السيرفر الأول (`cd server && npm run db:deploy && npm run dev`) ثم `npm run dev` للواجهة، وضبطي `CORS_ORIGIN` في `server/.env` على عنوان الواجهة.
